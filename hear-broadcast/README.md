# 聽見廣播 · 高頻聲波傳輸 PoC

用車站現有的廣播喇叭，以 18～19.3 kHz 高頻聲波傳送廣播內容，讓聽障者與外國旅客的手機即時顯示字幕。不需加裝硬體，接收端只要打開網頁。

## 檔案

| 檔案 | 說明 |
|---|---|
| `index.html` | 完整網頁（發送端＋接收端），已內嵌 `modem.js` |
| `modem.js` | 核心：連續相位 FSK 調變、前導碼同步、Reed-Solomon 錯誤更正 |
| `src/app.html` | 網頁原始檔（修改後把 `modem.js` 內嵌到 `/*MODEM*/` 位置即成 `index.html`） |
| `test.js` | 噪音與回音通道模擬測試：`node test.js` |
| `test_auto.js` | 自動偵測頻段測試：`node test_auto.js` |

## 使用方式

1. 開啟 GitHub Pages 網址（瀏覽器需要 HTTPS 才能使用麥克風）。
2. 筆電切到「發送端」，手機切到「接收端」並按「開始接收」。接收端預設「自動偵測」頻段，不必手動對齊。
3. 先用「15→20 kHz 掃頻」確認喇叭和麥克風能用到多高的頻率，再調整發送端的起始頻率。
4. 選擇廣播模板，按「發送一次」。

## 技術規格

- 18 個頻道（起始頻率 + i × 75 Hz，預設 18000～19275 Hz）：2 個同步音、16 個資料音（每個符號 4 bits）
- 柔和波形：頻率在每個符號前 15% 以餘弦曲線平滑切換，封包前後各有 100 ms 淡入淡出；落在 16 kHz 以下的雜音比舊版少約 60 dB
- 符號長度：標準 60 ms（約 67 bit/s）、穩定 100 ms
- 封包：前導碼 A B A B ｜ 長度 ｜ ~長度 ｜ RS(資料 + 6 位元組檢查碼)，最多可修正 3 個位元組錯誤
- 內容：傳「模板編號＋參數」（1.7 秒），字幕與多國語言由手機端離線模板產生

## 模擬測試結果（舊版 17 kHz 配置，各 30 次）

| 情境 | 標準模式成功率 |
|---|---|
| 安靜 | 100% |
| 中等噪音＋0.4 秒回音 | 100% |
| 強噪音＋0.8 秒回音 | 約 90～93% |
| 極強噪音＋1.2 秒回音 | 約 30～50%（穩定模式較佳） |

改版後（18 kHz、間距 75 Hz、柔和波形）在「強噪音＋0.8 秒回音」下以相同音量測試：29/30（舊版 27/30）。

## 自動偵測頻段

車站（發送端）在安裝時依現場喇叭選定頻段後就固定；乘客手機無法回傳，所以由接收端自己找：

1. **掃描**：同時監聽 8 組設定（16 / 17 / 18 / 18.5 kHz × 標準 / 穩定）。每組只計算同步音 A、B 與 4 個參考頻道，計算量約為完整模式的 1/3。
2. **鎖定**：第一則訊息解碼成功後，只保留該組，改用完整模式。
3. **重新掃描**：鎖定後 60 秒沒有收到訊息，自動回到掃描。

測試結果（各 24 次，發送端隨機使用 8 組設定之一）：安靜 23～24/24、中等噪音＋0.4 秒回音 24/24、強噪音＋0.8 秒回音 22/24；60 秒純噪音誤報 0 次；換設定後可自動重新鎖定。
